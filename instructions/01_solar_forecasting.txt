REQUIRED PUBLIC CONTRACT
Create a forecaster class with:

    predict(request: ForecastRequest) -> SolarProfile

The returned supply_kw must:
- contain exactly request.horizon_hours values;
- contain no NaN, infinity, or negative values;
- use aggregate simulated kW, not raw irradiance;
- include a useful model_name and metadata.

IMPLEMENTATION TARGET
1. Download and cache hourly NASA POWER data for Charlottesville.
2. Validate missing values and timestamps.
3. Build only features that are available at prediction time.
4. Use chronological train/validation/test splits.
5. Implement a month/hour historical-average baseline.
6. Train HistGradientBoostingRegressor or another agreed tabular regressor.
7. Evaluate MAE and RMSE against the baseline.
8. Save the fitted pipeline with joblib under artifacts/.
9. Implement loading and prediction behind SolarForecaster.
10. Preserve SeasonalDemoForecaster as the offline fallback.

DATA-LEAKAGE RULES
- Do not random-split time-series rows.
- Do not use future irradiance as an input.
- Shift rolling windows before computing them.
- If using future weather fields, document where those fields would be obtained
  at prediction time. Otherwise describe the output as expected solar supply,
  not a weather forecast.

ACCEPTANCE TESTS
- Repeated prediction with the same artifact and request is deterministic.
- Prediction contains 24 finite, nonnegative values.
- Nighttime values are zero or near zero and are clipped appropriately.
- Training dates precede validation dates; validation precedes test dates.
- Evaluation reports the baseline and trained-model metrics.
- Existing tests/test_contracts.py continues to pass.
